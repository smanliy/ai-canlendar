# Claude‑Code 分层上下文压缩 & 长会话记忆管理

## 技能元信息

- 技能名称：Claude‑Code Compaction 五层金字塔压缩机制
- 适用场景：LLM Agent 长会话上下文治理、Token 超限处理、任务中断续接、简历项目讲解、面试技术问答
- 核心目标：实现 Agent 长任务无缝接力，解决 Token 溢出、Lost-in-the-Middle、工具调用时序断裂问题
- 核心设计思想：上下文管理不是单纯节省 Token，而是**信息分通道治理，按记忆半衰期分层保留**

## 1. 何时使用

当你需要处理以下任务时，优先使用本技能：

1. 长会话总结、压缩、续接
2. 任务中断后重新接力
3. Claude Code 相关机制说明、面试讲解、项目复盘
4. 需要解释上下文爆炸、工具调用堆积、记忆保留策略

## 2. 背景与痛点

普通对话与 Agent 智能体在上下文消耗上存在巨大差异，Agent 天然更容易打爆上下文窗口：

1. 固定开销高：System Prompt、工具描述、`CLAUDE.md` 常驻，预先占用 5k-10k token。
2. 工具调用成对消耗：每次工具调用生成 `tool_use` + `tool_result` 两条消息，返回结果文本往往很长。
3. 文件读取、Shell 命令、检索输出极易快速撑满上下文。

仅依靠扩大上下文窗口无法根治问题：

- 推理成本、延迟上升。
- 存在大模型固有缺陷：Lost-in-the-Middle，长文本中间信息容易被模型忽略。

### 传统上下文方案缺陷

| 方案          | 缺点                                                                               |
| ------------- | ---------------------------------------------------------------------------------- |
| 滑动窗口      | 直接删除早期历史，丢失初始目标、依赖关系，强行遗忘换取续航                         |
| 固定 N 轮摘要 | 触发时机死板、摘要粒度不可控，容易丢失关键细节                                     |
| RAG 向量召回  | 破坏对话时序；切断 `tool_use/tool_result` 的成对绑定关系；召回结果和当前上下文割裂 |

## 3. 五层压缩金字塔

> 层级之间为渐进式防护；上层优先执行，尽可能推迟重量级全量压缩。

### Layer 1：大工具结果落磁盘

- 规则：单条工具结果 > 50KB，完整内容写入本地磁盘；对话消息仅保留约 2KB 的预览摘要。
- 单消息工具结果总量上限：200KB。

### Layer 2：Snip 轻量裁剪

- 模型在正常对话回合内，通过 `snip` 工具按消息 ID 标记删除远古历史消息。
- 不发起独立的摘要请求，开销极低。
- 释放出的 Token 空间供给 Auto-Compact 使用，避免重复压缩。

### Layer 3：Micro-Compact 小时级清理

- 触发条件：距离上一次 API 调用超过约 60 分钟。
- 清理对象：可重新获取的工具结果（Read、Bash、Grep、Glob、WebFetch、WebSearch、Edit、Write）。
- 保留策略：仅保留最近 5 条工具结果；**子 Agent 输出、Task 任务状态等不可重建信息禁止裁剪**。

### Layer 4：Context Collapse 读时动态投影（灰度实验）

- 触发阈值：上下文达到窗口 90% 开始预警，95% 升级压缩。
- 核心特点：**原始会话历史完整保存在本地，不会修改；仅在调用模型 API 时动态生成一份压缩视图**，属于读时投影。
- 和 Auto-Compact **互斥**，同一时刻只会运行其中一套机制；Context-Collapse 开启会短路 Auto-Compact 判断。

### Layer 5：Auto-Compact 自动全量摘要（兜底重型压缩）

> Claude-Code 对外版本最核心、最常落地使用的重型压缩方案。

#### Auto-Compact 三大核心思路

1. **绝对 Token 阈值触发，不按对话轮数、百分比触发**
2. **全量重写对话历史，不采用保留最近 N 轮的策略**
3. 信息分流：长半衰期语义信息存入摘要；运行时状态、异步任务不走摘要，走附件通道恢复

#### 安全阈值计算规则

1. 预先从原始上下文窗口划出 **20000 token**，专门预留用于摘要输出（来自统计 P99.99 摘要长度 17387 token，加上冗余）。
2. 设置运行安全缓冲：`13000 token`
3. 距离窗口上限真实安全距离 ≈ `20000 + 13000 = 33000 token`

> 优势：绝对值固定，模型窗口扩容后触发线不会同步放大，资源可控。

## 4. 压缩后消息重组结构

压缩完成之后旧对话链被替换为全新 4 段消息结构：

1. **边界标记**：压缩类型（自动/手动）、压缩前 Token 用量、最后一条消息 ID
2. **结构化摘要 summary**：历史会话精华
3. **附件数据**：最近打开文件、日程计划、技能配置、异步子任务状态
4. **Hook 结果**：压缩阶段执行钩子脚本的输出

## 5. 关键资源分流保留策略

> 这一部分内容不走摘要通道，采用旁路机制恢复，防止丢失状态。

1. **CLAUDE.md（永久记忆文件）**
   - 不参与摘要；压缩时清空 `getUserContext` 缓存。
   - 下一轮请求自动重新从磁盘加载。
2. **System Prompt**
   - 不参与压缩；调用 `buildEffectiveSystemPrompt()` 重新构建，刷新工具列表、MCP 服务、权限配置。
3. **异步子任务状态**
   - 任务：运行中 / 已完成 / 报错；全部放入附件注入新上下文，保证主 Agent 不会丢失后台任务进度。
4. **活跃文件恢复预算（硬约束）**
   - 最多恢复最近 5 个文件。
   - 单文件上限：5000 token。
   - 文件恢复总预算上限：50000 token。
   - 文件选取规则：按最近访问活跃度优先排序。

## 6. 结构化摘要输出规范

### Prompt 前置强制约束

> 摘要任务禁止调用任何工具（Read/Bash/Grep 等）；仅允许输出纯文本。  
> 设置双重警告防止模型在摘要阶段执行工具调用。

### XML 输出格式

```xml
<analysis>
模型草稿思考区，该部分最终会被剥离，不会送入后续上下文
</analysis>
<summary>
1. Primary Request and Intent：用户原始目标
2. Key Technical Concepts：项目关键技术概念
3. Files and Code Sections：涉及文件、代码模块
4. Errors and fixes：出现过的错误以及修复方案
5. Problem Solving：问题解决路径
6. All user messages：所有用户发出过的指令、需求变更，不可遗漏
7. Pending Tasks：排队待执行任务列表
8. Current Work：当前正在执行任务，精确至文件、函数级别（接续任务最核心字段）
9. Optional Next Step：可选下一步计划
</summary>
```

## 7. 执行要求

当使用本技能时，输出应遵循以下原则：

1. 不丢失原始信息。
2. 只做整理、整合、重排，不做无依据删改。
3. 若内容用于讲解，优先保留机制、参数、阈值、流程、边界条件。
4. 若内容用于技能文档，优先保留“何时用、怎么做、输出什么、如何验收”。

## 8. 验收标准

- 关键机制完整保留
- 五层结构清楚
- 触发条件、阈值、预算清楚
- 摘要结构清楚
- 旁路恢复策略清楚
- 适合直接交给 Codex 继续执行或二次整理

## 9. 一句话结论

Claude-Code 的压缩机制本质上不是“删历史”，而是**按信息半衰期分层治理上下文，并通过摘要、附件、缓存与文件恢复来维持长任务连续性**。
